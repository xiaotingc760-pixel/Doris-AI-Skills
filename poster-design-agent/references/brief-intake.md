# 需求采集规范

## 1. 目标

在不打断创作的前提下建立轻量 Brief。默认从用户描述、附件与上下文自动填充，先交付概念方案，再在结果末尾集中列出正式投放所需信息。

## 2. 内部采集信息

以下字段是 Agent 的内部检查清单，不应原样作为问卷发给用户。优先自动识别；无法识别时标记为“待确认”或采用安全假设。

### 业务信息

- 业务类型
- 产品／服务名称
- 实际服务提供方
- 商户／平台／资金方关系
- 活动名称
- 活动时间
- 投放地区

### 用户信息

- 核心目标用户
- 用户当前需求
- 用户主要顾虑
- 用户决策因素
- 用户预期动作

### 营销信息

- 本次核心目标
- 核心卖点
- 辅助卖点
- CTA
- 跳转页面
- 是否涉及价格、折扣、赠品、分期、利率、额度等

### 设计信息

- 投放渠道
- 交付尺寸
- 横版／竖版
- 是否需要多尺寸适配
- 是否有品牌 VI
- Logo 文件
- 产品图
- 字体要求
- 色彩要求
- 禁用元素
- 竞品／参考图

## 3. 信息状态

所有信息标记为：

- 已确认
- 待确认
- 安全假设
- 阻塞

### 仅阻塞正式投放的典型示例

- 业务类型不明确但用户要求精确金融宣传
- 金融服务提供方不明确且需要在正式稿中展示主体
- 价格／优惠没有确认
- Logo 或品牌授权不明确
- 投放尺寸未知且用户要求正式交付
- 用户要求正式投放但活动时间、规则未确认

上述项目不阻塞安全概念稿。概念稿应删除未经确认的事实承诺，使用无品牌素材、通用文案或明确占位，并在交付末尾说明替换项。

## 4. 最小提问规则

默认不提问，先给方案或出图。只有用户明确要求正式投放／精确复刻，且缺失信息会导致事实错误、侵权或金融误导时，才提问。

- 一次最多询问 3 个关键问题。
- 合并同类问题，不分多轮追问。
- 能用安全概念方案继续时直接继续。
- 不要求用户先选择业务类型编号。
- 不要求用户填写完整 Brief。
- 待确认项放在结果末尾，不作为开场回复。

## 6. 可安全假设范围

可安全假设仅用于视觉探索，例如：

- 产品居中或偏右构图
- 深色科技风／浅色生活方式风
- 24px 或 32px 的模块间距
- CTA 使用高对比按钮

不可安全假设：

- 价格
- 折扣
- 利率
- 月供
- 额度
- 产品参数
- 品牌授权
- 活动资格
- 监管资质
- 用户收益
