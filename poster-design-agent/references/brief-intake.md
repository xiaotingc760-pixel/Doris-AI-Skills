# 需求采集规范

## 1. 目标

在任何正式视觉设计、生成提示词或投放审核前，建立可追溯的设计 Brief，避免因业务信息不完整导致返工、误导或合规风险。

## 2. 必采集信息

### 业务信息

- 业务类型
- 产品／服务名称
- 实际服务提供方
- 商户／平台／资金方关系
- 活动名称
- 活动时间
- 投放地区

### 用户信息

- 核心目标用户
- 用户当前需求
- 用户主要顾虑
- 用户决策因素
- 用户预期动作

### 营销信息

- 本次核心目标
- 核心卖点
- 辅助卖点
- CTA
- 跳转页面
- 是否涉及价格、折扣、赠品、分期、利率、额度等

### 设计信息

- 投放渠道
- 交付尺寸
- 横版／竖版
- 是否需要多尺寸适配
- 是否有品牌 VI
- Logo 文件
- 产品图
- 字体要求
- 色彩要求
- 禁用元素
- 竞品／参考图

## 3. 信息状态

所有信息标记为：

- 已确认
- 待确认
- 安全假设
- 阻塞

### 阻塞项典型示例

- 业务类型不明确
- 金融服务提供方不明确
- 价格／优惠没有确认
- Logo 或品牌授权不明确
- 投放尺寸未知且用户要求正式交付
- 用户要求正式投放但活动时间、规则未确认


## 5. 可安全假设范围

可安全假设仅用于视觉探索，例如：

- 产品居中或偏右构图
- 深色科技风／浅色生活方式风
- 24px 或 32px 的模块间距
- CTA 使用高对比按钮

不可安全假设：

- 价格
- 折扣
- 利率
- 月供
- 额度
- 产品参数
- 品牌授权
- 活动资格
- 监管资质
- 用户收益
